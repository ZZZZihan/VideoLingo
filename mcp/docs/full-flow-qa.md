# 完整流程验收与问题修复

日期：2026-10-29。验收范围：本地 MCP 视频转录、Codex 翻译、中文字幕与双语字幕、视频导出、异常恢复和多客户端并发。本机为 macOS ARM64 / Python 3.12，识别后端为 faster-whisper 1.2.1 / PyAV 18.1.0。

## 真实完整流程

使用本地语音合成制作 48.916667 秒测试视频，含两种英文声音、句间停顿、日期时间、金额和八句完整内容。素材是专门制作的测试输入，不是用户正式视频。

整条链路通过官方 MCP SDK 的真实 stdio 客户端调用，使用本机生成的 Codex 配置中的命令、工作目录和环境：

1. `health` 后经 `start_transcription` 启动默认 `small` 模型识别，未导入预制字幕替代识别。
2. 识别期间断开客户端，重连后通过 `get_job` 读取完成状态。
3. 经 `get_transcript` 每页两段取回八段真实识别结果。
4. 当前 Codex Agent 根据识别内容翻译，通过 `save_translations` 分批保存。只保存第一段时尝试导出，明确拒绝不完整结果；全部保存后继续。
5. 导出中文、双语各一份 SRT 和 VTT。
6. 分别导出中文和双语 MP4；每次启动后断开 stdio，重连后读取 `completed` 和产物。
7. 从两个成品 MP4 再次提取字幕，逐段核对全部文本；核对三种流、完整时长、原文件 SHA-256。

最终生成六份有效产物，所有中文、双语内容与提交内容一致，均含八个字幕片段；MP4 没有被字幕结束时间截短，原视频未改变。另以三秒真正静音音轨运行缓存 tiny 模型，返回“未识别到有效语音”的失败状态，没有虚构字幕或发布产物。

本机证据保留在 `.scratch/qa-20261029/full-flow/`：`calls.jsonl` 为 MCP 调用记录，`verified.json` 为产物核对结果，`ground-truth.json` 与 `transcript.json` 可比较识别质量；`silence-result.json` 记录静音测试。成功任务 ID 为 `d52bd4f01efd4bb982a5aae518f4f836`。这些运行数据、模型和视频不进入 Git。

## 已复现并修复的问题

| 问题 | 修复后的行为 | 回归证据 |
| --- | --- | --- |
| 多音轨输入只保留第一条音轨 | MP4 导出映射全部音轨，并保留语言标签 | 两音轨真实输出与 ffprobe 检查 |
| 重叠字幕被 mov_text 静默截短或生成零时长片段 | 导入及渲染提前明确拒绝重叠；精确相接的片段仍合法 | 重叠/同起点/相接边界测试 |
| 孤立 Unicode surrogate 保存时才编码失败 | 文本校验阶段拒绝不可编码字符 | 字幕与翻译校验回归 |
| 处理开始后替换源视频仍发布成功结果 | 处理前后检查大小、修改时间及新任务的设备号/inode，变化时失败并撤回本轮输出 | 普通修改和保留大小/mtime的原子替换 |
| 处理进程退出后，忽略 SIGTERM 的后代仍继续运行 | 按整个进程组执行终止宽限期及 SIGKILL，不以组长退出作为完成 | 真实不响应 TERM 的后代进程验收 |
| 执行进程被硬杀后留下临时 MP4 | 所有处理失败分支均清理本任务未发布的导出目录 | 真实 SIGKILL 注入与临时目录检查 |
| Linux 旧版 FFmpeg 把 VTT 中的普通反斜线、花括号当作 ASS 指令，丢字或改变换行 | 仅将视频导出临时 VTT 的这些标点归一化为全角；独立 VTT 和原始转录不改 | 提取 MP4 字幕精确比对、源 VTT 字节不变；具备 libass 时对照归一化参考字幕的烧录画面 |
| macOS 进程退出过渡及仅剩僵尸进程的进程组返回 EPERM，清理再次报错后任务遗留处理中状态 | Darwin 的退出过渡有界重试 0.5 秒，仅在组长已退出且进程列表确认无活成员时视为空组；真实权限或查询故障保留失败。清理异常仍保存失败终态，提前取消不再启动媒体进程 | 系统僵尸/活后代实证、确定性错误边界测试及修复后 10 次双客户端立即取消、30 次真实父子进程取消 |

故障测试还覆盖无音轨、损坏输入、缺少离线模型、监督进程中断后重连与重新导出。媒体测试覆盖双语特殊符号、字幕时序、长文本、超大片段的明确失败、已有文件/目录/符号链接保护、无音轨和奇数画面尺寸。

并发测试使用两个独立 MCP 服务进程共享任务目录，检查分批翻译并发保存不会丢失更新、两个媒体任务的限制跨进程有效，以及导出期间不会接受改译文操作。

远程 CI 仅在 `mcp/` 或对应工作流变动时运行，权限为 `contents: read`，不下载语音模型、不调用付费 API。GitHub 检查结果以 PR 的实际运行状态为准，不能用本地测试结果代替远程结果。

## 验证边界与已知限制

- full-clip small 识别将第六句的 “Background processing” 识别成了 “And processing”；同一原句单独识别时可正确识别。此次译文忠于实际识别结果，未悄悄用测试原稿覆盖转录。它说明语音识别仍需内容复核，不代表流程故障，也不构成逐字准确性保证。
- 硬字幕成功分支在本机无法执行，必须看具备 libass 的环境检查；当前本机交付仍以可切换字幕轨为主。
- 已经验证实际 Codex 配置启动的 MCP 协议全流程。桌面 UI 工具明确禁止访问 Codex 应用，因此本轮未声称完成当前聊天的界面重载或人工验收。
- 未针对长达数小时、真实多人重叠讲话、严重噪声或所有语种做质量评估；当前会明确拒绝时间重叠的字幕输入。
- 用户授权的是在其自己的 VideoLingo 仓库中创建 PR；没有执行合并、发布或部署。
